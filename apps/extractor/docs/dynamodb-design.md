# DynamoDB Schema Design

## Overview

The AI Injury Extractor uses DynamoDB as the storage layer for extracted injury entries.

The goal is to store the original user-provided injury description together with structured information generated by the LLM (Groq API).

The MVP focuses on:

- Raw injury descriptions
- AI-extracted injury information
- Retrieving previously stored injury entries

---

## Table Design

### Table Name

`InjuryEntries`

---

## Primary Key Design

DynamoDB uses a composite primary key:

| Key           | Name        | Purpose                        |
| ------------- | ----------- | ------------------------------ |
| Partition Key | `userId`    | Groups injury entries by user  |
| Sort Key      | `timestamp` | Stores entries chronologically |

Example:

```text
userId                 timestamp
-------------------------------------------
test-user-001          2026-08-01T10:00:00Z
test-user-001          2026-08-03T15:30:00Z
test-user-001          2026-08-04T09:15:00Z
```

This design allows future queries such as:

- Retrieve injury history for a user
- Retrieve entries ordered by date
- Display previous injury records

---

## Example DynamoDB Item

```json
{
  "userId": "test-user-001",
  "timestamp": "2026-08-04T10:30:00Z",
  "entryId": "uuid",

  "rawText": "I hurt my left knee doing squats two weeks ago. Pain is 6/10.",

  "extractedData": {
    "injury_name": "Knee injury",
    "body_area": "left knee",
    "pain_level": 6,
    "symptoms": ["pain during exercise"],
    "possible_causes": ["squats"]
  }
}
```

## Design Decisions

### Single-item injury record

For the MVP, each injury extraction is stored as a single DynamoDB item.

Reason:

- Simple storage model
- Matches current Lambda workflow
- Easy retrieval of injury entries
- Avoids unnecessary complexity during early development

The consuming Injury Tracker application may use a relational model (for example PostgreSQL/Prisma) to manage:

- Users
- Injuries
- Symptoms
- Treatments
- Medical visits
- Timeline events

---

## Future Improvements

Possible future additions:

- Add authenticated user identity instead of temporary `userId`
- Improve partition key and sort key strategy based on access patterns
- Add DynamoDB Streams for event processing
- Export data to S3 for analytics workloads
- Add AI-generated tags and search capabilities
